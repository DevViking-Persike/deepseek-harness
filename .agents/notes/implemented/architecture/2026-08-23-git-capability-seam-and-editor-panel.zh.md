# Agent Note: Git 能力 seam 与编辑器的版本控制面板

Status: implemented

[English](2026-08-23-git-capability-seam-and-editor-panel.md) | 中文

## Problem

在一个会改文件的 agent 旁边，人最常做的事就是审阅尚未提交的改动，而 harness 此前完全没有 Git 能力：没有 seam，没有工具，也没有浏览器界面。一切都得走 `bash`——模型要解析无界的 CLI 文本，harness 无法限制输出，UI 也只能把结果画成终端文本。

这个缺口比"不方便"更严重。agent 和人同时修改同一个工作区。若没有一个界面显示改了什么、谁暂存了什么、这个分支还能不能推送，人就只能另开一个终端窗口——从而失去了"正在审阅的文件"与"正在编辑的文件"之间的联系。

设计由三个真实机器上的事实决定。一个工作区不止一个仓库：monorepo 带着子模块，人也会把多个项目并排放着。一个仓库不止一个检出：`git worktree add` 让每个检出拥有自己的 HEAD、自己的索引、自己的工作区，而共享同一个对象数据库。分支能否安全推送，取决于其基线分支是否在脚下前进——`main` 或 `develop` 前进，正是让推送被拒绝、或产生一个无人评审的合并提交的原因。

## Decision

Git 访问是一个遵循[能力 seam Agent Note](2026-06-13-capability-seams.md) 的能力 seam，其浏览器面板位于编辑器标签页**内部**而非旁边：

1. `@deepseek-ai/dsh-git`（`packages/git/git`）持有 `ctx.git`、提供方注册表、提供方选择、请求/结果词汇以及 `GitError`。
2. `@deepseek-ai/dsh-git-local`（`packages/git/git-local`）通过 `ctx.subprocess` 驱动本机 `git` CLI。
3. `@deepseek-ai/dsh-tool-git`（`packages/git/tool-git`）持有面向模型的 schema、提示词段落、输出上限与呈现。
4. `packages/host/apiproxy/src/api/git.ts` 声明浏览器侧的 `git.*` 域。
5. `@deepseek-ai/dsh-client-ui-git` 向编辑器标签页的面板环注册一个面板。

选择规则与 [docker seam](2026-08-21-docker-capability-seam.md) 一致，且从不依赖注册顺序。可用性按调用重新探测而非缓存：仓库会在一次普通会话中被初始化、克隆或删除，缓存的答案会把操作送往一个已经不适用的后端。

### 后端是 CLI

`git-local` 以固定 argv 执行 `git`，绝不使用 shell 字符串，并把每个路径放在 `--` 之后，使得名字形似选项的文件仍被当作路径。

索引格式、重命名检测、`.gitattributes` 过滤器与工作区解析，正是 JavaScript 重新实现会在每个 Git 版本上产生偏差的部分。本 seam 的全部价值在于与用户自己终端里的 `git` 保持一致，因此无论依赖多少，重新实现都是错误的取舍。

每次读取都请求机器可读格式，而 `-z` 分帧正是让含空格、换行与非 ASCII 名称的路径安全的原因：记录以 NUL 分隔，路径从不加引号或转义。三条分帧规则决定了解析器，每一条都取自真实 `git` 运行的记录而非假设：

- `status --porcelain=v2 -z` 中，**重命名**占用两条记录（条目本身，然后是原路径）；`diff --numstat -z` 中占用三条（计数带空路径，然后旧路径、新路径）。
- **二进制**文件的两个 numstat 计数都报告 `-`，这是"没有行信息"，而不是"零行"。
- **未说明原因的锁定工作区**只发出裸标志，但仍必须读作已锁定——这决定了是否可以提供移除操作。

缺失的事实保持缺失而不变成错误：没有上游的分支完全不输出 `# branch.ab`，读作零偏离；未诞生的分支报告 `(initial)`，读作没有 head 提交。

### 面板位于编辑器标签页内部

面板占据 `conversation.view.editor.panel` 这个由编辑器标签页声明、并通过其 `Files | Source` 切换器渲染的槽位。

一个并列的 `conversation.view` 标签页是显而易见的备选，但更差。审阅改动与编辑改动共享同一棵文件树、同一个缓冲区、同一个会话；两个标签页会把三者都复制一遍，并把一条工作流劈成两半。在标签页内部，点击一个已改动文件会在编辑器自己的缓冲区中打开它，而重写了当前打开文件的丢弃操作会请求编辑器重新加载——owner props 正是为此携带 `openFile` 与 `reloadBuffer`。

这一放置还消除了一个架构问题，而不是绕开它。编辑器持有 Monaco 加载器，而 `packages/client/AGENTS.md` 禁止导入另一个插件包的符号；并列标签页若想使用同一个缓冲区就需要一个例外。子槽位通过 owner props 传递所需内容，这是被认可的路径。

### 索引两侧是彼此独立的事实

`GitFileChange` 分别携带 `index` 与 `worktree`，单侧改动中缺席的一半读作 `unmodified`，使消费方在一个封闭联合上做穷尽分支。

Git 的两字母状态确实是两个事实：一个文件可以被暂存为新增，然后又被再次修改。把它们合并成一个词，恰恰会让 UI 无法在同一行上同时提供暂存与取消暂存，也会让模型无法判断一次提交究竟会包含什么。

### 每个检出都可寻址，改动跟随当前显示的检出

`git.worktrees` 列出每个检出及其分支、状态与**改动路径数量**，因此一次调用即可回答每个检出里有什么，而不必每行发一次请求。裸仓库与可修剪的检出不报告数量，因为二者都没有可读的工作区。

面板的改动操作寻址的是当前显示的检出，而非仓库根。每个工作区拥有自己的索引与工作区，因此在一个里暂存绝不能触碰另一个；有一条测试通过断言传给 `stage` 的路径来钉住这一点。

### 丢弃会保留它所销毁的内容

`discard` 在恢复路径**之前**先用 `hash-object -w` 把被替换的内容写入对象数据库，并返回其 `recoveredOid`。RPC 行与 `git_discard` 工具都会呈现该 id。

这是此处唯一可能丢失未提交工作的操作。使其可恢复，正是允许它出现在一个不经 agent 中介的域上的理由，也是编辑器的丢弃通常不提供的保证。

### 推送安全性是一次读取，且不触碰任何东西

`git.compareBases` 将检出与部署方的集成分支（`main`、`origin/main`、`master`、`develop` 及其远程写法）比较，报告 `ahead`、`behind` 以及合并回去是否会冲突。

`behind > 0` 是决定推送是否安全的事实，因此面板据此告警，而在分支仅仅领先时保持安静——领先是进行中工作的常态。冲突答案来自 `merge-tree --write-tree`，它在对象数据库中计算合并：不移动任何 ref，不写入任何工作区文件，因此在推送前询问既无成本也无副作用。仓库没有的基线会被略去，而不是显示为空行。

### 图谱即泳道，泳道分配是纯函数

`git.graph` 返回带父提交的提交列表以及锚定它们的分支；`lanes.ts` 将其转换为列与边，`GitGraph.tsx` 用 SVG 绘制。

布局规则是图谱渲染器共同收敛到的那一条：泳道在提交被抵达之前就已被其子提交预留，第一个父提交继承该泳道（使线性历史保持在一列），合并的每个后续父提交各占一条（把合并画成汇聚的线束）。汇聚的线束收拢到**最左**列，使历史回归主干，而不是沿页面向右漂移。

泳道分配是与组件分离的纯函数，因为拓扑正是图谱渲染器出微妙错误的地方——画错列的线束会误判一个提交属于哪个分支——而这类错误只有在隔离状态下才易于捕获。选用 SVG 而非 CSS 盒子，是因为关键在于边，而边框技巧无法表达它。

### RPC 与工具的界线，以及唯一的例外

读取，加上操作者对眼前工作区施加的改动（`stage`、`unstage`、`discard`、`commit`）位于 `git.*` 域。改写共享历史或触及远程的操作——revert、reset、push、pull——留在域外，走 agent 的工具，由会话日志记录。

从面板直接提交是对本仓库 *model-visible ⟺ logged* 规则的**有意例外**。docker seam 正是依据该规则拒绝了 UI 生命周期操作，而 Git 与之并不对称：`compose down` 改变的是工作区之外的机器状态，而提交一个人正看着的工作区，与 `editor.writeFile` 地位相同——后者本就无会话事件即可写入。因此面板同时提供**两条**路径——直接的 **Commit** 与提示 `git_commit` 从而让该轮次进入会话日志的 **Commit via agent**——后者的存在正是为需要审计轨迹的人准备的。

### 读取工具默认开启，改动工具默认关闭

`tool-git` 独立注册 `inspect`（默认 true）与 `mutate`（默认 false），随附的 `packages/bundle/base/cordis.patch.yml` 明确写出两者。读取不会损坏仓库。改动组会销毁未提交的工作（`git_discard`）并写入历史（`git_commit`），因此启用它是部署方的决定。注册跟随启用而非可用性：已启用的工具在没有可用后端时依然可见，并以结构化的 `GitError` 失败，从而使插件加载顺序与机器状态永远不会进入面向模型的 schema。

## Alternatives considered

**让模型用 `bash` 操作 Git。** 拒绝。模型将解析无界的 CLI 文本，harness 无法限制 diff 或 log 输出，参数会被 shell 解释，UI 也只能把结果画成终端卡片。"随附读取、可选改动"的切分同样无法通过 shell 工具表达。

**使用 JavaScript 的 Git 实现（`isomorphic-git`、`nodegit`）。** 很有吸引力：结构化结果、无需 PATH 上的二进制、无需解析输出。拒绝，因为本 seam 的价值在于与用户自己的 `git` 一致。索引格式、重命名检测、`.gitattributes` 与工作区解析正是重新实现产生偏差之处，且每个 Git 版本都会再偏差一次。付出的代价是解析文本并依赖一个二进制。

**用并列的 `conversation.view` 标签页而非编辑器内部的面板。** 拒绝。它会复制文件树、缓冲区与会话，把审阅与编辑劈开，并且为了取用共享的 Monaco 加载器还需要对跨包导入规则开例外。

**每个文件合并成一个状态词。** 拒绝。Git 的两个事实正是让 UI 能在同一行提供暂存与取消暂存、并让模型知道一次提交会包含什么的原因。

**在第一个 `.git` 处停止发现。** 拒绝。子模块与 vendored 检出恰恰是审阅者需要看到的嵌套仓库；它们会被报告并标记。

**用 `git rev-parse` 探测每个被发现的目录。** 拒绝：每个候选目录一个进程。发现过程直接读取文件系统上任一种类的 `.git` 条目——子模块与链接工作区是以*文件*形式记录自己的，因此只检测目录会漏掉它们。

**由客户端分别请求每个工作区的状态。** 拒绝。计数正是这个列表值得绘制的原因，而每行一次调用会让常见情况（带多个检出的 monorepo）为一个问题付出 N 次往返。

**通过真实合并来检测冲突。** 直接拒绝：它会改动工作区，并可能留下冲突标记。`merge-tree --write-tree` 在对象数据库中回答同一个问题。

**只要分支有任何偏离就告警。** 拒绝。领先是进行中工作的常态；据此告警会训练人忽略横幅。只有 `behind > 0` 才威胁推送。

**所有提交都走 agent。** 作为唯一路径被拒绝，但它依然可用。在一个人正看着的工作区上提交是其本人的动作，与在旁边的编辑器里保存文件地位相同；为此强制一次模型轮次是只有摩擦而无对应保证的。带日志的路径是并列提供，而非取而代之。

**默认启用改动工具。** 拒绝。`git_discard` 会销毁未提交的工作；一个未经部署方表态就能这么做的默认值，站在了安全默认值的错误一侧。

## Testing

每一层都在其自身边界被钉住，且提供方层针对**每个测试各自创建的真实仓库**运行，而非脚本化的 CLI：任何能构建本仓库的机器上都有 `git`，而 stub 只能证明提供方传出了测试本就假设的 argv。

`git-local` 针对记录下来的输出覆盖上述三条分帧规则，另有针对真实仓库的覆盖：带空格与非 ASCII 名称的重命名、二进制文件、未诞生的分支、工作区（链接、游离、锁定、可修剪，以及从链接检出内部询问）、包含真实冲突的基线比较，以及包含合并与截断的图谱拓扑。冲突测试还断言其后工作区未被改动。

`git.*` 域**通过域方法本身的拒绝**来证明两道围栏，而非检视 schema：位于所有已注册工作区之外的仓库，以及位于其仓库之外的路径，在每一行上都被拒绝——包括每个改动行各自被拒，因为每一行都可被单独抵达。

`lanes.ts` 有自己的拓扑测试套件——线性、独立分支尖端、合并、章鱼合并、根提交，以及向左收拢——正是它捕获了最初的向右漂移缺陷。

`tool-git` 通过真实的工具注册表与真实的 `ctx.git`，覆盖按组注册、销毁，以及结构化 seam 错误抵达模型而工具保持注册。

## Consequences

**暂存以文件为单位，而非以 hunk 为单位。** `git.stage` 接受路径；hunk 协议尚无消费方，而 `git.diff` 返回的整文件内容在有消费方时足以支撑它。

**面板不会自行刷新。** 在其之外发生的改动——agent 编辑了文件——会在重新选择仓库或某个操作结算时出现，因为宿主不发布仓库变更事件。

**一次只提供一个恢复 id。** 在关闭提示前连续丢弃两次，会使第一个 id 只能通过对象数据库触及。

**没有 merge、rebase、branch、stash 或远程操作。** 每一项都是带有自身生命周期与中止点的状态机，或触及凭据；`GitChangeKind.conflicted` 与 `ahead`/`behind` 计数报告这些状态，但不提供解决手段。

**从面板提交不产生会话事件。** 即上文声明的例外；需要轨迹的人可走 agent 路径。

**一次 status 花费三次 CLI 调用。** status 加 numstat 两侧，因此病态仓库最多可耗费配置读取超时的三倍。

**发现过程读取文件系统而非 `git`。** `.git` 存在但已损坏的仓库会被发现并在首次使用时失败——考虑到替代方案是每个候选目录一个进程，这是诚实的顺序。
