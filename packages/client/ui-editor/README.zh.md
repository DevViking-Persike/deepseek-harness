# @deepseek-ai/dsh-client-ui-editor

[English](README.md) | 中文

Chat 旁的代码编辑器：浏览会话的工作区、打开文件、编辑并保存。

## 注册内容

一个 `conversation.view` 条目（`id: 'editor'`、`order: 30`），因此它位于 Chat、Trajectory 与 Docker 之后。该页签是一个文件树，旁边是 [Monaco](https://github.com/microsoft/monaco-editor) 缓冲区。

## 并发编辑

每次写入都携带该文件被读取时的 `FsVersion`。如果一次保存会覆盖此后发生的编辑——通常来自在同一工作区中工作的 agent——宿主会以 `editor-stale` 拒绝它，页签随即提供重新加载，而不是悄悄取胜。任何一侧的工作都不会在未被展示的情况下丢失。

文件树根目录跟随所寻址会话自身的 `cwd`，因此在另一个项目中打开的会话显示的是那个项目，而不是部署自身的目录。

## 语言支持

| 关注点 | 来源 |
|---|---|
| 语法着色 | harness 调色板（`--shiki-token-*`），从实时文档中读取，因此这里的代码与聊天消息中的代码保持一致 |
| 缩进 | `language-configs.ts` —— 规则 vendor 自 microsoft/vscode（MIT）；C# 为手工编写，因为上游未提供 |
| 悬停、定义、引用 | `lsp` seam，当某个组合挂载了它时 |

Monaco 在没有 web worker 的情况下运行，回退到主线程语言服务。高亮、折叠、查找与多光标可用；跨文件 IntelliSense 不可用。

## 模型体验

无，因为本包为人类渲染工作区文件，不触及 prompt、消息、schema、流或工具结果。

#### KV Cache 影响

无；本包从不组装或发送 provider 请求。

## 已知限制与暂缓事项

- **没有补全，也没有内联诊断** —— `lsp` seam 刻意只开放四种语义查询（定义、引用、实现、悬停），而诊断是推送式的，那套请求/响应约定无法承载它。
- **一次只打开一个文件** —— 多标签页需要一个能在重新挂载后存活的 store，而目前没有消费方提出这一需求。
- **没有项目级搜索** —— `grep` 仍是 agent 用于此事的工具，在浏览器中复刻它需要它自己的 RPC 域。
- **保存是整文件的** —— 大文件在每次保存时都会重新发送其全部文本；diff 协议目前没有消费方。
- **纯文本没有语法着色** —— `.txt` 及其同类解析为 Monaco 的 `plaintext`，而它没有关键字；它们只获得编辑器的背景、行高亮与行号槽。
