# @deepseek-ai/dsh-client-ui-docker

[English](README.md) | 中文

Web Docker 检视特性的归属方：基于宿主只读的 `docker.*` RPC 域，向 `conversation.view` 贡献一个条目——位于 Chat 与 Trajectory 旁的 **Docker** 页签。本包不定义服务，也不声明任何 Context merge；它在视图环上注册一个 `order: 20` 的条目（Chat 更低，Trajectory 为 10），其标签经由 `docker` 命名空间跟随当前语言。

页签列出引擎已知的全部容器，已停止的也包括在内：刚刚退出的容器正是操作者打开这个页签要找的东西，只列运行中的容器会把待诊断的故障藏起来。每一行携带生命周期状态词、名称、镜像引用、容器带有相应 label 时的 compose 项目与服务、已发布端口，以及引擎自己的状态行。点击一行展开该容器最近的日志输出（长度由宿主截断），并在宿主或引擎丢弃了较早内容时如实说明。下方的第二个列表展示本地可用镜像及其标签——无标签镜像显示为 `<无标签>`——以及以最易读单位表示的大小。一个「刷新」控件同时重新加载两个列表与已展开的日志面板。

这里刻意没有生命周期控制。启动、停止与编排容器属于 agent 的 `dsh-tool-docker` 调用，会话日志会记录它们；一个不被记录的按钮会在没有任何会话记录的情况下改变机器状态。本页签读取的 RPC 域根本不提供这类操作，因此该排除在做出决策的那一层被强制执行，而不是靠这里少画几个按钮。

引擎不可达是一种普通状态，而非故障：Docker 已停止的机器，或者根本没有挂载 Docker seam 的组合，会返回 `docker-unavailable`，此时页签渲染一行平静的说明，告知没有可达的引擎——没有 alert role，没有错误配色，也不渲染列表区块。其他任何拒绝则如实报出其 code 与消息。每次读取都携带 `AbortSignal`：刷新与卸载会在线路上中止被取代的请求，而不只是丢弃其结果。

线路调用位于本包 `apply` 闭包内，而不是 [`dsh-client-runtime`](../runtime/README.md) 对象层的服务里，因为该域无状态且只有本插件读取——这里没有任何东西跨条目共享、被订阅，或在两次刷新之间缓存。

## 模型体验

无，因为本包为人类渲染宿主读取的引擎状态，不触及 prompt、消息、schema、流或工具结果。模型对同一批容器的视角仍属于 [`dsh-tool-docker`](../../docker/tool-docker/README.md)。

#### KV Cache effect

无；本包从不组装或发送 provider 请求。

## 已知限制与暂缓事项

- **列表只读且基于拉取** —— 该页签背后没有引擎事件流，因此在一次刷新之后启动或退出的容器要到下一次刷新才可见。实时更新需要 `docker` RPC 域目前不提供的宿主侧 watch。
- **日志面板一次只显示一个容器** —— 展开第二行会收起第一行；面板读取宿主的默认 tail，不提供行数选择或跟随模式。
