# @deepseek-ai/dsh-client-ui-knowledge

[English](README.md) | 中文

一个设置分区，展示会话可以依托的内容：它能调用的 skill、它受约束的决策记录，以及它可以阅读的文档。

## 本包注册了什么

一个 `settings.section` 条目（`id: 'knowledge'`，`order: 25`），位于「插件」之后、「Agent 预设」之前。管理一个部署所知道的内容属于配置，而非逐会话的工作，因此它是一个设置页面，而不是一个对话页签。

## 来源是承重的一列

提交到项目中的 skill 与只存在于操作者主目录中的 skill，在 prompt 层面表现完全相同，对其他所有人却截然不同。因此本分区把注册表的 source id 归入三种来源：

| 显示为 | 注册表来源 | 含义 |
|---|---|---|
| 项目 | `project-dsh`、`project-agents` | 随仓库提交；每位协作者都能获得 |
| 全局 | `user-dsh`、`user-agents` | 仅限本机 |
| 内置 | 其余全部 | 由当前运行的组合提供 |

注册表中 `-dsh` 与 `-agents` 的区分对 loader 有意义，对阅读者没有意义，因此二者在这里合并为同一种来源。

## 数据从哪里来

skill 经由既有的 `skill.list` RPC 获得。决策记录与文档是普通 Markdown，通过编辑器域中受 workspace 围栏约束的 `listDir` 与 `readFile` 读取，因此本分区不会新增第二条通往磁盘的路径。

记录只读取其根目录下一层——一篇笔记归档在它的种类之下（`implemented/architecture`）——项目中不存在的目录会被跳过而不报告，因为一个没有 `docs/adr` 的仓库是常态，而非损坏。

## 模型体验

无，因为本包为人类呈现一个会话可以触及的内容，不触及 prompt、消息、schema、流或工具结果。它不改变抵达模型的内容。

#### KV Cache 影响

无；本包从不组装或发送 provider 请求。

## 已知限制与暂缓事项

- **只读** —— 安装、启用、停用或编辑 skill 仍然发生在文件系统上；线路上不承载其中任何一项的变更操作。
- **知识目录是一份固定列表** —— `docs/adr`、`.agents/notes/proposed`、`.agents/notes/implemented`、`docs` 与 `.agents`。把记录归档在别处的项目会看到空白面板，而让这份列表可配置需要一个本包并不拥有的设置命名空间。
- **Markdown 以纯文本展示** —— 渲染会把一整条 Markdown 流水线引入一个设置页面，而该页面的用途是定位文档，不是长篇阅读。
- **记录只列出一层** —— 嵌套更深的已归档笔记不会显示。归档并非当前记录，但该面板也因此不是一份详尽的文件清单。
